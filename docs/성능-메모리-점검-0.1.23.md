# LightCapture 0.1.23 반응성과 메모리 점검 결과

2026-10-30. 연속 편집 드래그와 목록 체크에서 지연을 확인해 개선했다. 개선 후 4K 드래그의 p95는 약 5~8ms였으며, 첫 화면 준비와 PNG 저장·복사는 여전히 순간 지연이 있다. 모든 동작이 항상 부드럽다고 단정할 수는 없다. 정보 보기의 다른 캡처 도구 비교 문구는 제거했다.

## 측정 범위와 해석

사용자 PC에서 별도 합성 데이터 폴더와 숨긴 앱으로 검사했다. 사용자 화면·클립보드·캡처 보관함을 읽거나 변경하지 않았다. 그림·텍스트·선택 영역·붙여넣기·확장·Undo·목록·저장·삭제 경로는 자체 핸들러로 실행했다. 화면 그리기는 앱 자신의 메모리 DC와 WM_PRINT를 사용했다. 실제 마우스 입력부터 모니터 표시까지의 지연이나 DWM·GPU 합성 시간은 아니다.

1920×1080 및 3840×2160 합성 화면을 사용했다. 개선 전 자료는 0.1.22와 같은 렌더링 경로에 측정 기능만 추가한 빌드이며, 개선 후에는 같은 동작을 반복했다. p95는 관측 표본의 95백분위다. 단발 작업은 1~3회여서 참고치이며 장시간·다른 하드웨어를 대표하지 않는다. 세부 표본 수와 최댓값은 JSON에 있다.

## 반복 동작의 개선 전후

| 동작 | 해상도/목록 | 개선 전 p95 | 개선 후 p95 |
| --- | --- | ---: | ---: |
| 펜 드래그+그리기 | Full HD | 32.64ms | 4.47ms |
| 펜 드래그+그리기 | 4K | 96.09ms | 4.62ms |
| 캔버스 그리기 | 4K | 103.55ms | 5.82ms |
| 선택 영역 이동 | 4K | 83.79ms | 7.85ms |
| 선택 영역 크기 조절 | 4K | 82.38ms | 6.38ms |
| 텍스트 상자 이동 | 4K | 92.68ms | 5.49ms |
| 붙인 이미지 이동 | 4K | 95.21ms | 5.55ms |
| 목록 체크 | 100장 | 54.38ms | 13.17ms |

4K 펜 드래그 p95는 약 20.8배 빨라졌다. 60Hz의 16.7ms 예산보다 대부분의 반복 프레임은 짧았지만, 새 배경 캐시를 만드는 첫 프레임에는 최대 약 80~94ms가 관측됐다. 이 수치를 실제 표시 FPS로 해석하지 않는다.

## 메모리 사용량

단위는 MiB(1,048,576바이트)다. 작업 집합은 현재 RAM에 올라온 프로세스 메모리이며 공유 DLL 등을 포함한다. 전용 메모리는 PrivateUsage이며 작업 관리자의 전용 작업 집합과 같은 항목은 아니다.

| 상태 | 작업 집합 | 전용 메모리 |
| --- | ---: | ---: |
| 처음 실행·빈 대기 | 15.77 | 2.85 |
| Full HD 편집 후 | 40.28 | 21.36 |
| 4K 편집 후 | 90.84 | 72.08 |
| 4K 작업 후 트레이 복귀 | 23.34 | 4.54 |
| 100장 목록 유지 | 24.66 | 5.51 |
| 그림판 추가·숨김 30회 후 대기 | 23.62 | 4.43 |

전체 측정 중 최대 작업 집합은 **224.80MiB**였다. 큰 이미지의 렌더·복사·인코딩 중 임시 버퍼가 포함된 값이다. 트레이 복귀 후에는 약 23~24MiB로 내려갔다. 실제 보이는 창, 다른 이미지·글꼴·DPI·프로세스 상태에 따라 달라진다.

반복 추가·숨김 10/20/30회에서 전용 메모리는 4.41/4.36/4.43MiB였다. GDI 객체는 30개, USER 객체는 66개로 유지됐다. 이 짧은 반복에서 지속 증가 양상은 관측되지 않았으며 장시간 누수 부재를 증명하지는 않는다.

저장·복사 인코딩과 첫 썸네일 생성은 현재 UI 스레드에서 처리한다. 외부 앱 붙여넣기와 Windows 파일·폴더 선택창 응답은 이 시간에 포함하지 않았다. 첫 썸네일·단발 인코딩을 백그라운드 작업으로 옮기는 일은 별도 설계가 필요하며 이번 변경에 섞지 않았다.

## 캡처 선택 화면과 회귀 검사

캡처 선택 오버레이는 합성 화면에서 픽셀 일치 6개 검사와 해상도별 60프레임 CPU 시험을 수행했다. 기존 렌더러의 비교 열은 초기 0.1.0 소스이며 다른 제품의 측정값이 아니다.

| 합성 화면 | 현재 경로 p95 | 준비 시간 |
| --- | ---: | ---: |
| 1920×1080 | 0.461ms | 5.150ms |
| 3840×2160 | 0.626ms | 20.583ms |
| 7680×2160 | 0.719ms | 41.134ms |

핵심 49개, 복사 형식 11개, 오버레이 6개, 사각형 선택·이동·크기 조절 74개, 그림판·막대 23개, 확장·붙여넣기 50개 및 기존 텍스트·목록 자체 회귀를 확인했다. 표시 캐시의 픽셀·재사용·수정 후 갱신·크기 제한과 정보 문구 제거도 검사했다.

실제 전역 키부터 캡처 시작까지의 지연, 창 숨김 잔상, 다중 모니터·혼합 DPI, 실제 스크롤 캡처, 파일·폴더 대화상자, 외부 앱 클립보드 왕복은 이번 도구 사용 제한 안에서 조작 검증하지 않았다. 이 항목까지 포함해 모든 액션의 실체감을 확인하려면 별도 실제 조작 검증이 필요하다.

## 적용한 변경과 재현

- 화면에 맞춰 축소한 배경을 최대 16MiB 캐시로 재사용한다. 편집·원본 변경 때 갱신하고 트레이 숨김 때 해제한다. 큰 배율의 무제한 버퍼는 만들지 않는다.
- 목록 체크 시 재그리기를 한 번으로 묶고, 펜 굵기 패널의 표시가 실제로 바뀔 때만 전체 레이아웃을 갱신한다.
- 정보 보기에는 버전·현재 캡처 키·주요 편집 키·종료 방법만 표시한다.
- --benchmark --data <새 시험 폴더>로 같은 숨긴 앱 시험을 재현한다. 새 폴더를 사용해야 하며 사용자 데이터 폴더는 지정하지 않는다.
