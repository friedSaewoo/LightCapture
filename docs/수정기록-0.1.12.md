# LightCapture 0.1.12 이미지 복사 호환성 수정

2026-10-25. 사용자는 편집창의 이미지는 정상인데 카카오톡 등에 붙여넣을 때 회색으로 나타난다고 보고했다. 이번 수정은 복사 이미지 형식과 비트맵 전달 방식을 보강한다. 카카오톡 자체를 조작해 기존 문제를 재현하거나 해결을 확인한 결과는 아니다.

## 변경

- 이전의 DIBV5 + GetHBITMAP 전달을 PNG + 명시적인 24비트 CF_DIB + CF_DIBV5로 변경했다. 24비트 DIB는 일반 BITMAPINFOHEADER·BI_RGB·양수 높이·4바이트 정렬 행으로 작성한다.
- 세 형식 모두 같은 편집 결과를 사용한다. 투명 부분은 복사할 때 흰색으로 합성하고 알파값은 불투명으로 통일한다. PNG 저장 파일의 투명도는 변경하지 않는다.
- 이미지 인코딩과 메모리 할당을 마친 뒤 클립보드를 열며 잠시 점유된 경우 제한된 재시도를 한다. 실패하면 기존 이미지를 복사했다고 표시하지 않는다.
- 현재 사진의 디스크 보관본을 다시 읽어야 하는 경우 복사 전에 복원한다. 편집 캔버스의 회색 여백을 캡처하거나 복사하지 않고 원본과 편집 명령으로 결과를 만든다.
- 화면 수집에서 GDI에 선택한 비트맵을 FromHBITMAP으로 변환하던 경로를 제거했다. 명시적인 DIBSection에 GDI 픽셀을 받은 뒤 GdiFlush하고 별도 소유 ARGB 이미지로 복사한다. 화면 입력의 미정의 알파값은 255로 정규화한다. 이 결함이 사용자가 보고한 카카오톡 증상의 확정 원인이라고 단정하지 않는다.

표준 CF_DIB·CF_DIBV5·CF_BITMAP의 의미는 [Microsoft 표준 클립보드 형식 문서](https://learn.microsoft.com/en-us/windows/win32/dataxchg/standard-clipboard-formats)를 참고했다. [Bitmap::FromHBITMAP 문서](https://learn.microsoft.com/en-us/windows/win32/api/gdiplusheaders/nf-gdiplusheaders-bitmap-fromhbitmap)는 현재 또는 과거 DC에 선택한 비트맵의 전달을 금지하고 원본 GDI 객체의 수명을 요구한다. 이번 화면 입력 경로는 해당 API에 의존하지 않는다.

## 확인한 범위

핵심 회귀 시험 49개와 기본 복사 형식 시험 11개를 통과했다. PNG를 다시 디코딩하고 24비트 DIB·DIBV5와 모든 픽셀을 비교해 크기·행 방향·색상·알파 일치를 확인했다. 홀수 폭의 행 패딩, 투명·반투명 픽셀의 흰 배경 합성, 합성 메모리 DC에서 픽셀을 가져온 뒤 GDI 원본 버퍼를 파괴해도 결과가 유지되는 것을 검사했다. 자체 숨긴 앱의 복사 명령·편집·삭제·저장 회귀도 통과했다.

실제 별도 창 스테이션을 이용한 클립보드 시험은 일반 권한에서 Windows 오류 5로 생성이 거절됐다. 기본 자동 시험은 사용자 클립보드에 쓰지 않는다. 실제 시스템 클립보드 시험 수행 여부는 `verification/v0.1.12/`에 별도 기록하며, 기록이 없다면 기본 픽셀 시험만 수행한 것이다.

2026-10-25 추가 확인: 사용자가 현재 클립보드를 검증 이미지로 바꾸는 것을 허용한 후 시스템 클립보드 확장 시험 **27개를 통과**했다. 실제 게시·닫기·재열기·읽기를 2회 반복했으며 PNG·CF_DIB·CF_DIBV5 픽셀 및 Windows 변환 CF_BITMAP의 원래 색상을 확인했다. 27개는 기본 11개를 포함한다. 실행 파일은 변경하지 않았으며 이 검증 결과만 추가했다. 근거는 `verification/v0.1.12/clipboard-native-tests.txt`이다.

Computer Use·카카오톡 입력·메시지 전송·사용자 화면 수집을 수행하지 않았다. 실제 카카오톡 붙여넣기와 물리 키 입력·대형 이미지 지연·장시간 메모리는 별도 조작 검증이 남는다.

## 업데이트 사용법

트레이에서 구버전을 종료한 뒤 0.1.12 실행 파일을 연다. 정상 사진을 목록에서 선택하고 Ctrl+C로 다시 복사한 다음 카카오톡에서 Ctrl+V를 누른다. 이전 클립보드 내용은 새 파일 실행만으로 교체되지 않는다. 캡처 직후의 자동 복사는 추가하지 않았다.
